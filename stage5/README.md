# ПР22. Визуализатор графа зависимостей Cargo — Этап 5

## 1. Общее описание

Учебный проект (вариант 22): CLI-инструмент, который собирает сведения
о зависимостях пакетов Cargo (Rust) и визуализирует их в виде графа.

На этапе 5 реализована визуализация: граф переводится в текстовый
формат диаграмм **PlantUML**, текст сохраняется в `.puml`, а PNG-файл
(имя задаётся параметром `--output`) получается с сервера PlantUML.
Диаграмма сжимается zlib и кодируется в URL — только стандартная
библиотека Python.

Реализация этапов 1–4 сохранена без изменений.

## 2. Функции

- `src/visual.py`:
  - `plantuml_text(graph)` — строки `A --> B` между `@startuml/@enduml`;
  - `encode_plantuml` / `encode_bytes` / `encode_chunk` — кодирование
    deflate-данных в URL-алфавит PlantUML (A–Z, a–z, 0–9, `-`, `_`);
  - `save_text(text, file_name)` — сохранение `.puml`;
  - `save_png(graph, file_name)` — скачивание PNG с сервера.
- `src/main.py` — печать графа, текста диаграммы и сохранение файлов.

## 3. Запуск и тесты

Windows: запустите `run.bat`. Linux: `sh run.sh`.

Программа работает в интерактивном режиме и не закрывается, пока не
введена команда `exit`. После приглашения `>` можно вводить: строку
аргументов программы, `test` (тесты) или `exit` (выход). Пустой Enter
просто показывает приглашение заново.

Для PNG нужен доступ в интернет (plantuml.com). При недоступности
сохраняется `.puml` — его можно открыть на https://www.plantuml.com
или в IDE с плагином PlantUML.

## 4. Примеры визуализации (три пакета тестового репозитория)

Все команды вводятся после приглашения `>`.

1. Пакет A (`test_repo.txt`):

```
> --test-mode --package A --url test_repo.txt --output a.png
A -> B, C
...
Текст диаграммы PlantUML:
@startuml
A --> B
A --> C
B --> D
C --> D
@enduml
Сохранено: a.puml
Изображение сохранено: a.png
```

2. Пакет B (`test_repo.txt`):

```
> --test-mode --package B --url test_repo.txt --output b.png
B -> D
D -> -
Сохранено: b.puml
Изображение сохранено: b.png
```

3. Пакет A с циклом (`test_repo_cycle.txt`):

```
> --test-mode --package A --url test_repo_cycle.txt --output c.png
A -> B
B -> C
C -> A, D
Сохранено: c.puml
Изображение сохранено: c.png
```

4. Реальный репозиторий:

```
> --package serde --url https://index.crates.io --output serde.png
```

5. Нет интернета — PNG недоступен, текст сохраняется:

```
> --test-mode --package A --url test_repo.txt --output a.png
PNG недоступен (HTTP Error ...); используйте .puml
или сайт plantuml.com
```

6. Неверное имя файла:

```
> --test-mode --package A --url test_repo.txt --output a.jpg
Ошибка: файл изображения должен иметь расширение .png
```

7. Запуск тестов:

```
> test
Ran 31 tests in 0.022s

OK
```

8. Выход:

```
> exit
```

## 5. Сравнение со штатными инструментами Cargo

Штатные средства (`cargo tree`, `cargo depgraph`, `cargo graph`)
рисуют граф по локальному `Cargo.lock`. Ожидаемые расхождения:

1. **Версии.** Cargo показывает конкретные (в т.ч. дублирующиеся)
   версии пакетов; наш граф — только имена, версии берутся последние.
2. **Features и platform-зависимости.** Cargo учитывает их; мы берём
   все обычные зависимости из индекса.
3. **Дубликаты.** Cargo может рисовать один пакет несколько раз (по
   версии); у нас пакет — одна вершина.
4. **Циклы.** отображаются одинаково как рёбра, но layout сервера
   PlantUML отличается от layout Graphviz, используемого cargo-утилитами.
