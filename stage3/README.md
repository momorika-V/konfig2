# ПР22. Визуализатор графа зависимостей Cargo — Этап 3

## 1. Общее описание

Учебный проект (вариант 22): CLI-инструмент, который собирает сведения
о зависимостях пакетов Cargo (Rust) и визуализирует их в виде графа.

На этапе 3 реализованы основные операции: построение графа зависимостей
с учётом транзитивности алгоритмом DFS **без рекурсии** (стек), фильтрация
пакетов по подстроке, корректная обработка циклических зависимостей и
режим тестирования — анализ графа из текстового файла, где пакеты
названы заглавными латинскими буквами.

Реализация этапов 1–2 сохранена без изменений.

## 2. Функции

- `src/graph.py`:
  - `TestRepoLoader` — источник данных из тестового файла (формат
    строки `A: B, C`; пустые строки и `#`-комментарии игнорируются);
  - `CargoLoader` — источник данных из crates.io (версия пользователя
    применяется к корневому пакету, остальные — последняя версия);
  - `build_graph(start, loader, filter_sub)` — итеративный DFS:
    стек, множество посещённых пакетов (защита от циклов),
    отфильтрованные пакеты в анализ не попадают;
  - `print_graph(graph)` — построчный вывод `пакет -> зависимости`.
- `src/main.py` — выбор источника по `--test-mode` и запуск анализа.

## 3. Параметры запуска

Не изменились с этапа 2 (`--package`, `--url`, `--test-mode`,
`--version`, `--output`, `--filter`). В тестовом режиме `--package` —
одна заглавная буква, `--url` — путь к файлу графа.

## 4. Запуск и тесты

Windows: запустите `run.bat`. Linux: `sh run.sh`.

Программа работает в интерактивном режиме и не закрывается, пока не
введена команда `exit`. После приглашения `>` можно вводить: строку
аргументов программы, `test` (тесты) или `exit` (выход). Пустой Enter
просто показывает приглашение заново.

## 5. Примеры использования (тестовый репозиторий)

Все команды вводятся после приглашения `>`.

1. Обычный граф (`test_repo.txt`: A→B,C; B→D; C→D):

```
> --test-mode --package A --url test_repo.txt
A -> B, C
B -> D
C -> D
D -> -
```

2. Граф с циклом (`test_repo_cycle.txt`: A→B→C→A), программа
   завершается корректно — повторный заход в посещённый пакет
   не выполняется:

```
> --test-mode --package A --url test_repo_cycle.txt
A -> B
B -> C
C -> A, D
D -> -
```

3. Фильтрация (не показывать пакеты с D в имени):

```
> --test-mode --package A --url test_repo.txt --filter D
A -> B, C
B ->
C ->
```

4. Пакет D отдельно:

```
> --test-mode --package D --url test_repo.txt
D -> -
```

5. Несуществующий тестовый файл:

```
> --test-mode --package A --url no_such.txt
Ошибка: файл тестового репозитория не найден: no_such.txt
```

6. Реальный репозиторий (serde):

```
> --package serde --url https://index.crates.io
serde -> serde_derive
```

7. Запуск тестов:

```
> test
Ran 23 tests in 0.017s

OK
```

8. Выход:

```
> exit
```
