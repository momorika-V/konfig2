# ПР22. Визуализатор графа зависимостей Cargo — Этап 2

## 1. Общее описание

Учебный проект (вариант 22): CLI-инструмент, который собирает сведения
о зависимостях пакетов Cargo (Rust) и визуализирует их в виде графа.

На этапе 2 реализован сбор данных: приложение получает прямые
зависимости заданного пакета нужной версии из sparse-индекса crates.io
(https://index.crates.io) напрямую по HTTP и выводит их на экран.
Менеджеры пакетов и сторонние библиотеки не используются — только
стандартная библиотека Python (urllib, json).

Реализация этапа 1 (параметры и их проверка) сохранена без изменений.

## 2. Параметры запуска

| Параметр      | Назначение                                   | По умолчанию |
|---------------|----------------------------------------------|--------------|
| `--package`   | Имя анализируемого пакета                    | —            |
| `--url`       | URL репозитория или путь к тестовому файлу   | —            |
| `--test-mode` | Режим работы с тестовым репозиторием (флаг)  | выключен     |
| `--version`   | Версия пакета (`latest` или `1.2.3`)         | `latest`     |
| `--output`    | Имя файла с изображением графа               | `graph.png`  |
| `--filter`    | Подстрока для исключения пакетов (этап 3)    | пусто        |

## 3. Функции

- `src/config.py` — разбор и проверка параметров (этап 1).
- `src/fetcher.py` — работа с crates.io:
  - `index_path(name)` — путь пакета в sparse-индексе (правила
    каталогов `1/`, `2/`, `3/X/`, `XX/YY/`);
  - `fetch_records(name)` — загрузка JSON-строк (по одной на версию);
  - `choose_record(records, version)` — выбор версии (`latest` — самая
    новая);
  - `direct_dependencies(name, version)` — пары (имя, требование) для
    обычных зависимостей (dev- и build-зависимости отбрасываются).

## 4. Запуск и тесты

Требуется Python 3.8+ и доступ в интернет (для реального репозитория).

Windows: запустите `run.bat`. Linux: `sh run.sh`.

Программа работает в интерактивном режиме и не закрывается, пока не
введена команда `exit`. После приглашения `>` можно вводить:

- строку аргументов программы, например
  `--package serde --url https://index.crates.io`;
- `test` — запуск модульных тестов;
- `exit` — выход.

Пустой Enter просто показывает приглашение заново.

## 5. Примеры использования

Все команды вводятся после приглашения `>`.

1. Прямые зависимости serde 1.0.200:

```
> --package serde --url https://index.crates.io --version 1.0.200
Прямые зависимости serde:
  serde_derive (=1.0.200)
  serde_derive (^1)
```

2. Последняя версия serde (latest):

```
> --package serde --url https://index.crates.io
Прямые зависимости serde:
  serde_derive (^1)
```

3. Несуществующая версия:

```
> --package serde --url https://index.crates.io --version 9.9.9
Ошибка получения данных: версия 9.9.9 пакета serde не найдена
```

4. Несуществующий пакет (сервер вернёт 404):

```
> --package no-such-pkg-xyz --url https://index.crates.io
Ошибка получения данных: HTTP Error 404: Not Found
```

5. Тестовый режим на этапе 2 ещё не поддержан:

```
> --test-mode --package A --url test_repo.txt
Режим тестирования будет поддержан на этапе 3.
```

6. Запуск тестов:

```
> test
Ran 16 tests in 0.011s

OK
```

7. Выход:

```
> exit
```
