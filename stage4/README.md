# ПР22. Визуализатор графа зависимостей Cargo — Этап 4

## 1. Общее описание

Учебный проект (вариант 22): CLI-инструмент, который собирает сведения
о зависимостях пакетов Cargo (Rust) и визуализирует их в виде графа.

На этапе 4 добавлена дополнительная операция: вывод порядка загрузки
зависимостей для заданного пакета. Порядок строится итеративным DFS
(без рекурсии): пакет записывается в список после всех своих
зависимостей, поэтому каждая зависимость идёт раньше зависящего от
неё пакета.

Реализация этапов 1–3 сохранена без изменений.

## 2. Функции

- `src/order.py`:
  - `load_order(graph, start)` — порядок загрузки; стек пар
    `(пакет, обработан)`, множество посещённых (защита от циклов);
  - `print_order(order)` — вывод списка с номерами шагов.
- `src/main.py` — после печати графа выводит порядок загрузки.

## 3. Запуск и тесты

Windows: запустите `run.bat`. Linux: `sh run.sh`.

Программа работает в интерактивном режиме и не закрывается, пока не
введена команда `exit`. После приглашения `>` можно вводить: строку
аргументов программы, `test` (тесты) или `exit` (выход). Пустой Enter
просто показывает приглашение заново.

## 4. Примеры использования (тестовый репозиторий)

Все команды вводятся после приглашения `>`.

1. Граф A→B,C; B→D; C→D (`test_repo.txt`):

```
> --test-mode --package A --url test_repo.txt
A -> B, C
B -> D
C -> D
D -> -
Порядок загрузки:
  1. D
  2. B
  3. C
  4. A
```

2. Цикл A→B→C→A (`test_repo_cycle.txt`):

```
> --test-mode --package A --url test_repo_cycle.txt
A -> B
B -> C
C -> A, D
D -> -
Порядок загрузки:
  1. D
  2. C
  3. B
  4. A
```

3. Пакет B отдельно:

```
> --test-mode --package B --url test_repo.txt
B -> D
D -> -
Порядок загрузки:
  1. D
  2. B
```

4. Фильтрация (не показывать пакеты с D в имени):

```
> --test-mode --package A --url test_repo.txt --filter D
A -> B, C
B ->
C ->
Порядок загрузки:
  1. B
  2. C
  3. A
```

5. Несуществующий тестовый файл:

```
> --test-mode --package A --url no_such.txt
Ошибка: файл тестового репозитория не найден: no_such.txt
```

6. Реальный репозиторий (serde):

```
> --package serde --url https://index.crates.io
serde -> serde_derive
Порядок загрузки:
  1. serde_derive
  2. serde
```

7. Запуск тестов:

```
> test
Ran 26 tests in 0.022s

OK
```

8. Выход:

```
> exit
```

## 5. Сравнение с реальным менеджером пакетов

Для реального репозитория: `run.bat --package serde --url
https://index.crates.io`, порядок загрузки сравнивается с `cargo
tree` / `cargo build`.

Ожидаемые расхождения и их объяснение:

1. **Дубликаты версий.** Cargo может загружать один и тот же пакет в
   нескольких версиях одновременно (у нас версия одна).
2. **Платформенные и feature-зависимости.** Cargo учитывает target-
   зависимые и опциональные зависимости, включённые через features;
   наш инструмент берёт все обычные зависимости.
3. **Циклы.** В crates.io реальные циклы встречаются редко; при их
   наличии строгий порядок загрузки невозможен, и Cargo разрешает их
   своими правилами компиляции, а наш вывод — просто порядок обхода.
4. **Версии зависимостей.** Мы берём последнюю версию каждого пакета,
   Cargo подбирает версии по требованиям `req` из Cargo.lock/реестра.
